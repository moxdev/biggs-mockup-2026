# Biggs Website Testing Workflow

This file explains how to build the compiled Tailwind CSS and capture local screenshots for visual review. Use this workflow after homepage code changes, especially after BTW updates.

---

## Build Requirements

Build command:

```bash
npm run build:css
```

CSS input:

```text
src/input.css
```

CSS output:

```text
dist/output.css
```

Use compiled CSS only. Do not rely on the Tailwind CDN.

---

## Common Commands

Build CSS:

```bash
npm run build:css
```

Capture one section:

```bash
SECTION=home-awards npm run screenshots:section
```

Capture the full homepage:

```bash
npm run screenshots
```

Screenshots are saved in:

```text
testing/screenshots/
```

---

## Important: Do Not Edit This File for Each Test

Do not edit `TESTING.md` every time you want to test a different section.

Instead, change only the section ID in the terminal command.

Example:

```bash
SECTION=home-reviews npm run screenshots:section
```

Replace `home-reviews` with whichever section ID you want to test.

## Recommended Workflow After a BTW Update

After ChatGPT returns updated files:

1. Replace the updated files in the local project.
2. Run the section screenshot command for the section that changed.

Example:

```bash
SECTION=home-awards npm run screenshots:section
```

3. Upload the five section screenshots to ChatGPT.
4. Review feedback and make targeted changes if needed.
5. Run full homepage screenshots only if we need to check global page flow.

---

## Visual QA Checklist

When reviewing screenshots, check for:

- Text readability and contrast
- Elements squeezed too tightly
- Elements stretched too wide
- Overlapping cards, buttons, icons, or text
- Horizontal overflow
- Cropped images
- Cropped CTA buttons
- Broken mobile stacking
- Awkward tablet spacing
- Desktop sections feeling too sparse
- Consistent section padding
- Buttons remaining easy to tap on mobile
- Images staying clear and not distorted
- Shadows looking natural and not glowing unless intentionally designed
- Biggs Blue staying dominant
- Biggs Red and Biggs Yellow acting as accents
- Biggs Green used sparingly and mostly tied to Septic/Sewer

---

## BTW Testing Expectations

When running a BTW update, the preferred process is:

1. Rebuild Tailwind CSS after code changes.
2. Capture section screenshots for the edited section.
3. Review mobile, tablet, desktop, and wide desktop screenshots.
4. Confirm no layout, spacing, overflow, or readability issues.
5. Make corrections if needed.
6. Rebuild and capture screenshots again after corrections.
7. Return the updated files and summarize the changes.

Use section screenshots first. Use full homepage screenshots only when page flow needs to be reviewed.

## Clearing Old Screenshots

To avoid confusion, delete old screenshots before running a new test.

Run:

```bash
rm testing/screenshots/*.png
```

Then run the screenshot command again.

## Troubleshooting

### Screenshots are outdated

Delete old screenshots from:

```text
testing/screenshots/
```

Then rerun the screenshot command.

### Playwright browser is missing

Run:

```bash
npx playwright install chromium
```

Then rerun the screenshot command.

### CSS changes are not showing

Run:

```bash
npm run build:css
```

Then rerun the screenshot command.

### Section screenshot fails

Make sure the section ID exists in `index.html`.

Example:

```html
<section id="home-awards"></section>
```

Also make sure the command uses the exact same ID:

```bash
SECTION=home-awards npm run screenshots:section
```

### Port 4173 is already in use

Stop the existing local server and rerun the screenshot command.

If needed, find and stop the process using the port:

```bash
lsof -i :4173
```

Then stop the process using the listed PID:

```bash
kill -9 PID_NUMBER
```

Replace `PID_NUMBER` with the actual number shown in the terminal.
